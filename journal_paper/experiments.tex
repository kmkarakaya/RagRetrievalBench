\subsection{Shared Evaluation Setup}\label{shared-evaluation-setup}

\begin{itemize}
\tightlist
\item
  Retrieval backend: ChromaDB vector search with cosine similarity.
\item
  Cutoff: \texttt{k=10} for all metrics.
\item
  Chunking: \texttt{1000} size, \texttt{200} overlap.
\item
  Query count: \texttt{50} per dataset.
\item
  Candidate pool for qrels labeling: \texttt{20}.
\item
  Same five embedding models evaluated on each dataset.
\end{itemize}

Sources:

\begin{itemize}
\tightlist
\item
  \texttt{config.py} \citep{Config_Py}
\item
  Aggregate section \texttt{Methodology} and dataset raw-result \texttt{config} blocks. \citep{Aggregate_Report_2026_03_05, Raw_Education_Eng_2026_03_05, Raw_Education_Tr_2026_03_05, Raw_Law_Tr_2026_03_05}
\end{itemize}

Decision-support framing:

\begin{itemize}
\tightlist
\item
  this setup is intentionally fixed so users can compare retrieval quality and operational metrics to choose the best suitable embedding model for user/application requirements.
\item
  the workflow is designed for developers/practitioners and is pipeline reusable by any developer.
\end{itemize}

\subsection{Known Comparability Limitation}\label{known-comparability-limitation}

\texttt{law\_tr} has only 2 source PDFs but 723 chunks, while education datasets each have 29 PDFs. This structural imbalance can influence retrieval behavior and should be interpreted as a limitation when comparing cross-domain outcomes.

Sources:

\begin{itemize}
\tightlist
\item
  Aggregate \texttt{Dataset\ Statistics\ Summary}
\item
  Dataset sections under \texttt{Dataset-Specific\ Analysis} in aggregate report \citep{Aggregate_Report_2026_03_05}
\end{itemize}

\subsection{Report Outputs and Utility}\label{report-outputs-and-utility}

For each run, the pipeline emits:

\begin{itemize}
\tightlist
\item
  per-dataset benchmark reports (markdown/pdf),
\item
  aggregate cross-dataset report (markdown/pdf),
\item
  visualization assets for metrics, ranking, consistency, and timing.
\end{itemize}

These outputs are treated as automatic benchmarking reports across various metrics and as well-structured dynamic report outputs (timestamped markdown/pdf + visualizations) used for cross-dataset comparison for dataset-specific model selection.

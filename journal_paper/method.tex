\section{Method}\label{method}

\subsection{Pipeline}\label{pipeline}

The benchmark follows the repository pipeline implemented in \texttt{rag\_benchmark.py} and is designed as tooling for developer decision support. \citep{Rag_Benchmark_Py}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  Prepare corpus from dataset PDFs.
\item
  Generate synthetic queries from sampled chunks.
\item
  Generate qrels via LLM-based relevance judgments over retrieved candidates.
\item
  Initialize per-model vector collections.
\item
  Evaluate retrieval metrics and timing.
\item
  Generate per-dataset benchmark reports (markdown/pdf + visualizations).
\item
  Generate aggregate cross-dataset comparison reports.
\end{enumerate}

Datasets are isolated by \texttt{-\/-dataset} routing and \texttt{configure\_for\_dataset()} in \texttt{config.py}. \citep{Config_Py}

Pipeline purpose statement:

\begin{itemize}
\tightlist
\item
  enable selection of the best suitable embedding model for user/application requirements using local data and operational constraints.
\end{itemize}

\subsection{Metrics and Operational Measurements}\label{metrics-and-operational-measurements}

Retrieval metrics:

\begin{itemize}
\tightlist
\item
  \texttt{MAP@10}
\item
  \texttt{Recall@10}
\item
  \texttt{Precision@10}
\item
  \texttt{NDCG@10}
\item
  \texttt{MRR@10}
\item
  \texttt{Success@10}
\end{itemize}

Operational measurements:

\begin{itemize}
\tightlist
\item
  Embedding time and throughput (\texttt{chunks/sec})
\item
  Average query retrieval latency (\texttt{ms/query})
\end{itemize}

These outputs are intended to support cross-dataset comparison for dataset-specific model selection.

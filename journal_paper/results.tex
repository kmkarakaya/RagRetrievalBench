\subsection{Pipeline Utility for Model Selection}\label{pipeline-utility-for-model-selection}

The frozen outputs provide six quality metrics at \texttt{k=10} together with runtime measurements for all 5 models on all 3 datasets. This supports cross-dataset comparison for dataset-specific model selection and enables users to choose the best suitable embedding model for user/application requirements. \citep{Aggregate_Report_2026_03_05}

Dataset source provenance for this evaluation:

\begin{itemize}
\tightlist
\item
  Education datasets were curated from TED University regulations/guidelines source URL. \citep{TED_Regulations}
\item
  Law dataset was curated from BDDK regulations source URL. \citep{BDDK_Mevzuat}
\item
  Both sources were retrieved on \texttt{01/01/2026}. \citep{TED_Regulations, BDDK_Mevzuat}
\end{itemize}

\subsection{RQ2: Domain Effect Within Turkish (education\_tr vs law\_tr)}\label{rq2-domain-effect-within-turkish-education_tr-vs-law_tr}

For MAP ordering, the top-5 rank order is stable between \texttt{education\_tr} and \texttt{law\_tr} in this frozen run, with M5 ranked first in both datasets. \citep{Aggregate_Report_2026_03_05, Raw_Education_Tr_2026_03_05, Raw_Law_Tr_2026_03_05}

Domain-related differences are still visible in absolute scores and dataset-level difficulty:

\begin{itemize}
\tightlist
\item
  M5: \texttt{0.5508} (\texttt{education\_tr}) vs \texttt{0.3659} (\texttt{law\_tr}). \citep{Aggregate_Report_2026_03_05}
\item
  M3: \texttt{0.4876} vs \texttt{0.2948}. \citep{Aggregate_Report_2026_03_05}
\item
  Aggregate difficulty summary increases from \texttt{0.71} (\texttt{education\_tr}) to \texttt{0.79} (\texttt{law\_tr}). \citep{Aggregate_Report_2026_03_05}
\end{itemize}

Interpretation: this run supports domain impact in performance level/difficulty, while MAP rank ordering remains stable across the two Turkish datasets. \citep{Aggregate_Report_2026_03_05}

\subsection{Quality-Speed Tradeoff}\label{quality-speed-tradeoff}

Latency and throughput evidence shows a clear operational tradeoff:

\begin{itemize}
\tightlist
\item
  Fastest weighted query latency: M1 at \texttt{28.54\ ms/query}. \citep{Aggregate_Report_2026_03_05}
\item
  Slowest weighted query latency: M2 at \texttt{69.29\ ms/query}. \citep{Aggregate_Report_2026_03_05}
\item
  Highest mean MAP across datasets: M5 at \texttt{0.4857}, but with higher latency (\texttt{60.55\ ms/query}) and lower throughput than MiniLM variants. \citep{Aggregate_Report_2026_03_05}
\item
  Embedding throughput examples (chunks/sec): M1 roughly \texttt{48-57}, M5 roughly \texttt{14-15}, M2 roughly \texttt{3.9-8.6}. \citep{Aggregate_Report_2026_03_05}
\end{itemize}

Interpretation: the best MAP model is not the fastest model; model choice depends on quality-vs-latency constraints. \citep{Aggregate_Report_2026_03_05}

Practical implication:

the pipeline's automatic benchmarking reports across various metrics make this tradeoff explicit for real deployment decisions. \citep{Aggregate_Report_2026_03_05}

\subsection{Statistical Note}\label{statistical-note}

The aggregate report states that M5 does not significantly differ from M4 on MAP (\texttt{p=0.339}). \citep{Aggregate_Report_2026_03_05}
